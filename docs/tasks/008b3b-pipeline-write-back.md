## Objective
The workflow of 008b-2 gains a **write-back job** (under `environment: write-back`, holding only the App key) that, for each built version, publishes the Release in `worldofmodcraft/archive`, checks the project-owned `source_archive` URL through the front, and then opens and merges, one at a time, a same-repository pull request whose diff is exactly one T1 (`pending -> published`) transition — and, for a rejected version (008a exit 1) or a `+` version (092 Q10), exactly one T3 (`pending -> rejected`) transition — which passes the registry's own `gate` and merges under branch protection without bypass. `tools/pipeline/write_back_job.py` holds the sequencing loop, the pre-T1 check and the archive log rule behind injectable clock, GitHub and HTTP clients so they are tested offline; `tools/pipeline/release.sh` is the thin release step; the ownership carve-out for the App's bot id is 008b-3a and has merged before this task starts. This part also **removes the push gate** 008b-2 put on every job and proves the push trigger live (criterion 27), and adds the write-back job to the `summary` job's `needs`. A failed build's full log is posted where the author will see it. The App key is reachable only in runs on `main`, bound by the `write-back` environment.
